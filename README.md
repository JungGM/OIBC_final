현재 작업공간과 첨부된 파일을 먼저 조사하고, 확인된 OIBC 대회 제공 자료만 사용해 학습 데이터 전처리·특성공학·시간 순서 검증을 설계하고 구현해라. 목표는 발전소별 시간 발전량 예측을 학습할 수 있는 재현 가능한 데이터셋과, 어떤 특성이 정산 손실을 줄이거나 늘리는지 판단할 수 있는 검증 결과를 만드는 것이다.

## 작업 원칙

1. 먼저 `README.md`, 대회 문제정의서·공식 안내, 작업공간 파일 목록을 확인한다. README의 파일 경로·규칙과 실제 존재 여부를 대조하고, 없는 파일이나 확인하지 못한 규칙은 추측하지 말고 `미확인`으로 기록한다.
2. 첨부 자료의 현재 구조를 기준으로 시작한다. 확인된 자료는 `sites.csv`, `smp.csv`, `smp(1).csv`, `generation.parquet`, `forecast_wa(1).parquet`, `forecast_wb.parquet`, `observed_wa.parquet`, `observed_wb.parquet`, `README.md`다. 이름이 다른 파일은 내용과 기간을 확인해 용도를 판정한다.
3. 원본 대회 자료, 행 단위 예측, 모델 파일, 좌표와 개별 발전소 결과를 외부 서비스·저장소에 올리지 않는다. 좌표를 이용해 발전소의 실제 위치·사업자를 추정하거나 비식별을 해제하지 않는다. 허용 범위가 불명확한 외부 데이터는 가져오지 말고 보류한다.
4. 모든 시각은 README와 데이터에서 확인한 시간대·시간 구간 기준을 유지한다. 현재 자료는 KST, 1시간, 우측닫힘 시각이다. 키와 병합 기준을 명시하고, 타임존 제거·시각 이동·무단 반올림을 하지 않는다.
5. 전처리 설계와 결과는 “왜 처리하는지 → 데이터와 평가에 어떤 결과가 생겼는지 → 다음 결정을 어떻게 할지” 순서로 설명한다. 예측 특성 생성, 데이터 정리, 그룹 배정, 정산 평가는 구분한다.

## 먼저 출력할 데이터 점검표

각 파일별로 다음을 보고한다.

- 파일 존재 여부, 행·열 수, 컬럼명·자료형, 기간·시간대, 단위
- 키 후보와 키 중복 수, 결측 수와 비율, 값 범위·이상값, 시간 격자 누락
- 발전소·관측지점·라운드별 데이터 커버리지
- 조인 전후 행 수, 키가 맞지 않는 행 수, 중복 조인으로 행이 늘어나는지
- 실제 첨부 파일과 README에서 언급하지만 첨부되지 않은 파일 목록

초기 첨부 점검에서 확인된 사항은 반드시 재검증하고, 재현되면 처리 기록에 반영한다.

- `sites.csv`: 253개 발전소, `site_id` 중복·결측 없음. `lat/lon`은 이동·반올림된 비식별 좌표이므로 원위치 복구에 쓰지 않는다.
- 평가 `smp.csv`: 8,760시간, 2025-06-01 01:00~2026-06-01 00:00 KST, `ts` 중복 없음. `smp`에는 0원 시각이 있다.
- 학습 SMP(`smp(1).csv`): 38,688시간, 2021-01-01 01:00~2025-06-01 00:00 KST.
- `generation.parquet`: 4,392,566행, 253개소, 2021-01-19 13:00~2025-06-01 00:00 KST. `(site_id, ts)` 키 중복 여부를 다시 검사한다. 첫 점검에서 음수 `energy` 40행과 0 발전량 행이 확인됐다. 0은 결측으로 바꾸지 말고, 음수는 원본을 보존해 사유·처리 후보를 별도 보고한다.
- 제공사별 학습 예보에는 `round=10/17`이 있고, 관측 실측에는 발행 라운드가 없다. 예보 키는 `(관측지점, round, ts)`, 실측은 `(관측지점, ts)`다.
- `observed_wa.parquet`에서 첫 점검 기준 키 중복 6행이 있었다. 중복이 동일 값인지 충돌 값인지 조사하고, 병합 전 결정적 처리 규칙을 정한다. 근거 없이 첫 행만 남기지 않는다.
- `forecast_wb.parquet`의 강수·강설·결빙 관련 8개 열은 첫 점검에서 각각 1,298개 결측이었다. 해당 결측이 같은 행에 모였는지 확인한다.
- README에는 테스트 예보가 설명되어 있지만 이번 첨부 파일 목록에는 테스트 예보 Parquet가 없다. 실제로 찾지 못하면 평가용 특성 데이터는 만들었다고 주장하지 말고 필요한 파일을 명시한다.

## 예측 시점·누수 금지

예측 기준은 대상일 전날 17:00 KST다. 각 학습 행에 예측 기준시각(issue cutoff)을 만들고, 그 시각까지 알 수 있었던 입력만 허용한다.

- `round=17`을 기준 예보로 삼고 `round=10`은 이전 라운드 비교·수정량 특성으로 쓸 수 있는지 발행 시점과 규칙을 확인한다. README상 둘 다 예측 기준 전 발행으로 설명되어 있지만 실제 키·기간·가용성을 검사한다.
- 대상시각 이후의 실측 기상, 발전량, SMP, 평가 결과를 예측 입력으로 쓰지 않는다.
- `observed_wa/wb`는 실측값이다. 학습 구간의 예보 오차 분석·보정 연구에만 사용하고, 해당 대상시각의 실측 기상을 예보 입력인 것처럼 넣지 않는다. 보정값을 예측에 적용하려면 과거 자료만으로 학습한 시간순 교차적합 또는 과거 구간 추정치를 써서 누수 여부를 검사한다.
- `generation`의 과거 시차 특성은 실제 예측 기준시각에 발전량 데이터가 제공·수신됐음을 확인할 수 있을 때만 쓴다. 가용성이 확인되지 않으면 기본 모델에서 제외하고 별도 실험으로 격리한다.
- 평가지점 이후 기간을 임의로 학습·전처리·정규화·특성 선택에 사용하지 않는다. 모든 변환·결측 대체·선택 기준은 학습 fold 안에서만 적합한다.
- `smp`와 `k`는 정산 가중치 및 사후 평가에 사용한다. 대상 시간의 실현 SMP가 예측 기준에 제공됐다는 공식 근거가 없는 한 모델 입력에서 제외한다. 사용자 설명의 “2021~2022 급등”은 원인을 사실로 가정하지 말고 학습 SMP 시계열에서 급등 구간·분포 변화를 검증한다.

## 학습 행과 모델 입력

기본 학습 단위는 `(site_id, ts)`다. `generation.energy`를 타깃 `energy_kwh`로 두고, `sites.csv`의 용량·제공사별 관측지점 연결과 예측 기준에 유효한 기상 예보를 키로 병합한다. `current_group`은 참조 배정 열이므로 예측 특성에 기본 포함하지 않는다.

- 정산 대상은 발전소별 개별 오차가 아니라 배정된 그룹의 발전량 합계 오차다. 발전소 예측값은 그룹별 합으로 집계한 뒤 절대오차를 계산한다.
- 주 타깃은 kWh 예측이다. 용량 차이 영향을 분석하기 위해 `energy_kwh / capacity_kw` 형태의 용량 정규화 타깃을 비교 실험할 수 있지만, 최종 그룹 예측은 kWh로 환산하고 정산 점수로 선택한다.
- 발전량은 0 이상이어야 하며, 설비용량·시간 단위와 물리적으로 일치하는지 점검한다. 클리핑 여부는 검증자료에서 정하고 원본 타깃을 덮어쓰지 않는다.
- 발전소 ID, 좌표, 관측지점 ID 등 범주형·공간 특성은 누수와 과적합을 따져 개별 ablation으로 평가한다. 위경도는 제공된 비식별 좌표 그대로만 쓰고 원위치 탐색은 금지한다.
- 풍향 등 각도형 변수는 필요하면 sin/cos 변환한다. 제공사 A/B의 변수명·단위 차이를 보존하고, 풍속처럼 단위가 다른 변수는 검증된 단위 변환 후 비교한다. 특히 A 풍속은 m/s, B 풍속은 km/h다. 변환식·원본 단위를 특성 사전에 적는다.
- `forecast_wa`의 일전 기온·최고·최저 기온이 중복 또는 동일값인지 실제 데이터에서 확인하고, 중복 정보는 그룹 단위 중요도와 ablation으로 판단한다. 상관이 높다는 이유만으로 사전 제거하지 않는다.

## 요청한 14개 특성 항목

각 항목에 대해 생성 가능한 원천 컬럼, 계산식·시간 범위, 예측시점 가용성, 결측 처리, 누수 위험, 별도 실험 묶음을 특성 사전에 기록한다.

1. **SMP 급등 국면·정산 손실:** 학습 SMP의 시계열과 분포 변화를 분석해 고가격 구간을 정의한다. 사용자가 언급한 2021~2022 급등 원인을 검증 없이 특정 사건 탓으로 단정하지 않는다. 급등 구간을 삭제·축소·가중치 0 처리하지 말고 정상 학습에 포함한다. 정산 가중 SMP와 `k`를 사용해 고가격 시간대의 예측 오차 기여도를 따로 보고한다. SMP는 정산·분석 용도와 모델 입력을 분리한다.
2. **기상 제공사 A/B와 예보·실측 구분:** A와 B를 별도 소스·별도 변수군으로 유지한다. `forecast_wa/wb`는 예보 입력, `observed_wa/wb`는 학습 중 사후 오차 진단·보정 후보로 분리한다. 서로 다른 변수 구성과 단위를 억지로 동일 컬럼으로 합치지 않는다.
3. **계절 특성:** 월, 연중일, 계절을 범주형 또는 주기형 sin/cos로 만든다. 연도 자체의 학습·검증 분포 차이도 별도 보고한다.
4. **휴일 특성:** 요일·주말은 시각에서 계산한다. 한국 공휴일 자료가 대회 제공 또는 규정상 허용된 형태로 이미 있으면 공휴일·대체공휴일 여부를 추가한다. 외부 달력 반입이 불명확하면 임의로 수집하지 말고 공휴일 특성은 보류 사유를 기록한다.
5. **태양 고도:** 제공된 위경도와 시각으로 태양 고도·방위각, 일출·일몰 상대 위치를 계산할 수 있는지 검토한다. 좌표가 이동된 비식별 좌표라는 한계를 기록하고, 고도 기반 모델과 미사용 모델을 비교한다. 위치 복원은 하지 않는다.
6. **발전소 위치 특성:** `capacity_kw`, 제공사별 station ID·거리, 제한적으로 비식별 위경도·지역 파생치를 검토한다. 좌표 식별 시도는 금지한다. 위경도는 태양 고도 실험과 일반 위치 특성을 분리해 평가한다.
7. **결측 처리:** 행이 없는 `(site_id, ts)`와 실제 `energy=0`을 구별한다. 결측 타깃을 0으로 채우지 않는다. 입력 결측은 원인·비율·연속 길이를 검사한 뒤 학습 fold 내 대체, 결측 표시자, 제공사별 대체 또는 행 제외를 비교한다. 대체값 자체가 “비·눈 없음”을 뜻하지 않도록 한다.
8. **예보 수정량:** 같은 관측지점·대상시각에서 `round=17 - round=10` 차이와 절대 수정량을 계산한다. 라운드 간 대상시각·변수가 모두 매칭되는지 확인하고, 없는 짝은 결측 표시한다. 두 예보 라운드가 모두 cutoff 전에 사용 가능하다는 점을 검증한다.
9. **시간별 변화:** 예보 기상요소의 대상 시간 기준 전후 차분·기울기·강수 시작/종료 변화 등을 만든다. 차분은 같은 발행 라운드와 같은 관측지점에서 계산하고, 대상일 경계를 넘는 계산 규칙을 명시한다.
10. **하루 전체 패턴:** 전일 17시 시점에 확보 가능한 대상일 예보 24시간을 이용해 일별 평균·최대·최소·범위·변동성·일조 가능 시간·강수 시간·구름 변화량 같은 요약값을 산출할 수 있는지 확인한다. 24시간 입력이 불완전할 때 완전성 지표를 만들고, 미래 실측·발전량으로 요약값을 만들지 않는다.
11. **WA/WB 예보 차이:** 시간·관측지점 연결을 정확히 맞춘 뒤 대응되는 변수의 차이·절대차·방향 일치 여부를 만든다. 관측소가 서로 다르고 A/B 단위·정의가 다를 수 있으므로 `sites.csv` 매핑을 사용하고 비교 가능한 변수만 사용한다. 무리한 동일성 가정은 피한다.
12. **태양광 물리 특성:** 일사량 컬럼이 실제로 제공되는지 확인한다. 없으면 운량·태양 고도·시간을 조합한 간이 잠재 일사/낮 길이/태양 정점 특성을 실험 후보로 만들되, 관측 일사량으로 오인하거나 정확한 발전량 물리모델이라고 주장하지 않는다. 야간·태양 고도 이하 구간에서의 출력 제약도 실험한다.
13. **강설·결빙:** 강설량·강설확률·착빙량·결빙확률·기온·습구온도 등을 묶어 눈/결빙 위험 지표를 만든다. 제공사별 단위를 변환하고, 강수 열 결측과 실제 0을 구분한다. 변수 간 중복과 드문 이벤트 효과를 별도 평가한다.
14. **예보 품질:** 과거 학습 구간에서만 예보와 대응 실측의 오차·편향·결측률·이상률을 라운드·제공사·계절·시간대별로 계산한다. 대상시각 실측값은 예측 입력에 넣지 않는다. 실측으로 만든 품질 추정치는 과거 fold에서만 학습해 미래 fold에 적용한다.

## 결측·이상값·시간 격자 처리

- 각 파일의 키 중복을 먼저 검사한다. 중복이 동일 레코드인지 충돌 레코드인지 분류하고, 원본 행 수와 제거·집계 규칙을 로그에 남긴다. `observed_wa` 중복 6행은 반드시 구체적으로 조사한다.
- 결측값은 원인별로 분리한다: 파일/키 누락, 변수 단위 결측, 타깃 미관측, 발전소 운영 전 자료 등. 타깃 미관측은 학습·평가에서 제외하되 결측률·시간대·발전소 편향을 보고한다.
- 이상치 범위만 보고 자동 삭제하지 않는다. README의 경고 사례인 A 실측 풍속 9999, B 실측 운량 100 초과·UV 지수 15 초과·시정 50 km 초과·풍속 200 km/h 초과·기압 900 hPa 미만 등을 검사한다. 표시자·물리적 상한 대체·행 제외를 비교하고, 원본 보존과 처리 근거를 남긴다.
- 일괄 보간이나 앞/뒤 채우기는 금지한다. 사용하더라도 예측 cutoff 기준으로 과거 방향만 허용하고, 학습 fold 밖 정보를 참조하지 않는지 검사한다.
- 모든 조인 뒤 행 수, 키 유일성, 발전소별 시간 순서, 동일 시각 중복, 시간 격자 누락을 재검사한다.

## 시간순 검증과 정산 기준

무작위 행 분할을 쓰지 않는다. expanding-window 또는 rolling-origin 방식으로 과거 학습 → 미래 검증을 구성하고, 각 검증 구간의 첫 예측일 cutoff가 전일 17:00 KST인지 확인한다. 해당 검증 기간에 대해 `next_period_start - 1 day 17:00` 이후 정보가 학습·특성 생성에 섞이지 않도록 코드 수준 검사를 둔다. 튜닝·특성 선택에 쓰는 기간과 최종 미사용 확인 기간을 구분한다.

평가의 주 지표는 문제정의서의 정산 손실이다. README에 기재된 식과 공식 정의를 대조하고, 현행 문제정의서의 계수·동점 처리 등과 다르면 공식 정의를 따른다. 기본 비교 손실은 다음 구조로 계산한다.

`penalty = Σ_t SMP(t) × k(t) × |group_prediction(t) − group_actual(t)|`

절대오차는 각 발전소에서 먼저 계산하지 말고, 그룹별 예측·실적 발전량을 합산한 다음 계산한다. 제공된 평가 `smp.csv`와 `k`는 평가 가중치에 사용하되 모델 입력에는 넣지 않는다. 발전소별 MAE/RMSE, 그룹별 MAE/RMSE, 정산 손실, SMP 가중 손실 기여도는 각각 분리해 보고한다.

2021~2022 급등 또는 고 SMP 구간에 대해서는 손실 총액·오차·전체 손실 중 비중을 별도 산출한다. 해당 구간을 뺀 점수를 주 결과로 삼지 않는다. 고 SMP 시간대 성능이 나빠진 특성과 좋아진 특성은 검증 fold별로 재현되는지 확인한다.

## 중복 특성·중요도·증분 실험

성능을 확인하기 전 임의로 “중복” 특성을 제거하지 않는다. 다음 방법을 모두 사용해 핵심 특성을 정한다.

- 상관·결측 패턴·물리적 의미 기반 중복 후보 표
- 학습 fold 내 permutation importance 또는 SHAP 기반 중요도
- 상관된 특성은 개별 열뿐 아니라 논리적 특성군 단위 중요도
- 같은 시간 분할·타깃·그룹 구성·모델 조건에서 특성군을 하나씩 추가/제거하는 ablation
- fold별·연도별·고 SMP 구간별 결과와 변동성
- 성능이 좋아져도 다른 기간에서 악화되거나 발전소 편향이 생겼는지 점검

실험은 기준선에서 다음 묶음을 하나씩 추가하는 순서로 진행한다.

A. 기본 시각·용량·사이트 특성  
B. 계절·요일·허용된 휴일 특성  
C. 태양 고도·태양광 물리 파생 특성  
D. 제공사 A 예보(round 17)  
E. 제공사 B 예보(round 17)  
F. A+B 예보  
G. round 10 대비 수정량  
H. 시간별·하루 전체 패턴  
I. WA/WB 예보 차이  
J. 강설·결빙 특성군  
K. 과거 자료에서만 학습한 예보 품질 추정  
L. 합리적인 상호작용·용량 정규화 실험

각 실험은 동일한 시간 검증 구간에서 수행한다. 기준선, 추가 특성군, 변경된 특성군을 분명히 구분하며, 하이퍼파라미터를 바꾸는 실험은 입력 특성 실험과 섞지 않는다. 이득은 정산 손실 감소율과 절대 금액, MAE/RMSE 변화, fold 간 안정성으로 보고한다. 손실이 늘어난 특성도 숨기지 말고 증가량·가능한 원인·재현 여부를 기록한다. 실험 종료 후 이득이 재현되고 복잡도 대비 가치가 있는 특성만 최종 후보로 남긴다.

## 결과물

작업공간 안의 대회 자료와 모델은 로컬에만 둔다. 기존 파일을 덮어쓰지 말고, 별도 결과 디렉터리를 만든다. 최소 결과물은 다음과 같다.

1. `data_audit.md`: 파일 인벤토리, 스키마, 기간, 단위, 결측·중복·이상값, 파일 부재 및 한계
2. `feature_dictionary.csv` 또는 `.md`: 특성명, 수식, 단위, 원천 컬럼, 가용 cutoff, 결측 규칙, 누수 위험, 실험군
3. 학습 데이터 파일: 키·타깃·특성·타깃 관측 여부를 포함한 Parquet. 타깃 누락을 0으로 채우지 않는다.
4. 가능하면 동일 스키마의 평가 입력 데이터. 테스트 예보 파일이 없으면 생성하지 말고 누락 파일명을 기록한다.
5. `validation_splits.csv`: fold별 학습·검증 기간과 cutoff 경계
6. `feature_ablation.csv`: 실험 ID, 추가 특성군, 기준 대비 정산 손실 증감·감소율, MAE/RMSE 변화, fold별 결과
7. `feature_importance.csv`와 그림: 전체 및 특성군 중요도, 시간 검증 기준, 중요도 계산법
8. `quality_report.md`: 자동 검사 결과, 조인 전후 행 수, 키 유일성, 입력 범위, 물리적 검사, 타깃 누락 처리
9. 실행 스크립트와 설정 파일: 같은 명령과 설정으로 데이터 생성·검증을 재현할 수 있게 한다.
10. 마지막 요약: 어떤 특성이 손실을 줄였고 늘렸는지, 효과가 어느 기간·시간대에 나타났는지, 채택·보류 이유와 남은 불확실성을 표로 보고한다.

구현을 시작하기 전에 발견한 파일 목록과 데이터 감사 요약을 보여주고, 확인되지 않은 규칙·파일은 명시한다. 이후 위 원칙에 맞춰 코드를 작성하고, 생성된 결과물과 자동 품질 검사의 실행 결과를 보고한다.
